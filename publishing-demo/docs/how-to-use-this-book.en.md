📘 How to Use This Book

This is not a book you are expected to read from cover to cover.
It is a system designed to let you:

start at the right place, and stop at the right time.

This page explains:
who you are → how to use the book → when you are done.

What Problem Does This Book Solve?

This book solves one problem only:

How to turn writing and publishing into something verifiable, reproducible, and deliverable.

It does not promise better writing.
It guarantees that you can prove you have completed publishing.

If You Are a Reader (Individual Author)
How to Use This Book

Step 1 — Experience first, no theory

Look at this diagram. Do not read explanations yet:

Remember just one sentence:

Publishing is not “writing done” —
it is writing proven done by the system.

Step 2 — Run one command

From the project root:

make bootstrap && make build


Step 3 — Confirm completion

You are done when:

a dist/ directory exists

it contains:

a .zh.md file

a .en.md file

At this point, you have completed 80% of the book’s core value.

When Should You Continue Reading?

Only if you want to:

write long-term

collaborate with others

use this system structurally

Otherwise, you may stop here.

If You Are a Teacher / Instructor
How to Use This Book for Teaching

You can use this book without teaching theory.

Assign Route A as the only required task

Do not explain internals

Let students run the system

Grade by result, not explanation

Grading & Acceptance Standard

The book already defines the only valid evaluation method:

📄 Grading rubric:
docs/assessment/route-a-rubric.md

✅ Passing condition:

make bootstrap && make build


If it succeeds and dist/ exists → Pass

You do not need to:

read student content

judge writing quality

understand tooling details

The system output is the grade.

If You Are an Organization / Team / Publisher
What Is This Book for You?

You can treat this book as:

a publishing operating system

a repeatable onboarding template

a human + AI workflow with clear accountability

Recommended Adoption Pattern

Make Route A the minimum completion standard

Nothing proceeds unless Route A passes

Add collaboration, CI, and publishing only on top of Route A

What This Book Does NOT Require

This book does not require you to:

understand engineering

master tools

write “good content”

finish every chapter

If you can:

run Route A

explain what “verifiable completion” means

—you have learned the most important part.

When Can You Close This Book?

You may close the book when:

you have run Route A once

you have taught it once

you have successfully reused it elsewhere

Because this book is not meant to be read to the end,
but to be used until completion.

One-Sentence Conclusion

This is not a book that makes you smarter —
it is a system that makes results independent of smartness.
