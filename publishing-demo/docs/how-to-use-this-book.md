# 📘 本书如何使用

这不是一本要求你**从头读到尾**的书。  
这是一套允许你**在正确的位置开始，并在合适的位置停下**的系统。

本页将告诉你：  
**你是谁 → 该怎么用 → 什么时候算完成。**

---

## 一、本书解决什么问题？

本书只解决一个核心问题：

> **如何把“写作与出版”变成一件可验证、可复现、可交付的事情。**

它不承诺你写得更好，  
但它保证你**知道自己是否真的完成了出版**。

---

## 二、如果你是读者（个人作者）

### 你可以这样使用本书

1. **先体验，不要理解**
   * 看一张图：`docs/diagrams/route-a-mindmap.svg`
   * 跑一条命令：`make bootstrap && make build`

2. **确认你已经完成**
   * `dist/` 中出现 `.zh.md` 与 `.en.md`

3. **到这里你可以停下**
   * 你已经完成了本书 80% 的核心体验

### 什么时候继续读？

只有在你想：

* 长期写作
* 多人协作
* 或系统化使用

才需要继续阅读后续章节。

---

## 三、如果你是教师 / 培训者

### 本书可以直接这样用

* 把 **路线 A** 作为唯一必修作业
* 不讲原理，先让学生跑通
* 评分只看结果，不看解释

### 教学验收标准

本书已经为你定义好了**唯一验收方式**：

* 📄 评分标准：`docs/assessment/route-a-rubric.md`
* ✅ 通过条件：`make bootstrap && make build` 成功

你不需要：

* 阅读学生正文
* 判断写作质量
* 理解技术细节

系统输出本身，就是评分依据。

---

## 四、如果你是组织 / 团队 / 出版方

### 你可以把这本书当作什么？

* 一套**写作与出版的操作系统**
* 一个**可复制的入职 / 培训模板**
* 一条**AI 可介入但责任清晰的生产线**

### 推荐落地方式

1. 统一使用路线 A 作为最低完成标准  
2. 所有项目必须“可验证通过”才能进入下一阶段  
3. 后续流程（规范、CI、发布）**只能在不破坏路线 A 的前提下增加**

---

## 五、本书不要求你做的事

请放心，本书**不要求你**：

* 理解工程原理
* 学会复杂工具
* 写出“好内容”
* 一次性掌握全部章节

如果你已经：

* 跑通过路线 A
* 能解释什么是“可验证完成”

那么你已经学会了本书**最重要的部分**。

---

## 六、什么时候你可以合上这本书？

你可以在任何一个节点合上这本书：

* 跑通一次闭环后  
* 完成一次教学后  
* 把体系成功复制给他人后  

因为这本书的目标不是“被读完”，  
而是**被使用完**。

---

## 本页结论

> **这不是一本让你变得更聪明的书，  
> 而是一套让结果不再依赖聪明的系统。**
