附录 E｜路线 A 的常见失败与处理方式

这一附录用于：读者自救 / 教师答疑 / 助教手册

E.1 失败类型一：系统拒绝继续（QA 未通过）

表现：

make qa 失败

make build 被中断

正确处理：

停止执行

阅读失败信息

仅修复导致失败的最小问题

错误做法（禁止）：

跳过 QA

手动修改结果

用说明代替系统输出

E.2 失败类型二：没有生成 dist/

表现：

命令执行完成

但 dist/ 目录不存在

含义：

完成没有发生。

处理方式：

不接受解释

不接受截图

必须重新运行系统

E.3 失败类型三：“我确认已经完成”

这是最常见、也最危险的失败。

任何以下表述：

“逻辑上已经完整”

“内容已经检查过”

“只是小问题”

在 MVPL 体系中一律无效。

E.4 失败的正确地位

失败不是否定，
而是完成边界的提示。

所有失败，
都发生在完成之前，
因此是安全的。
